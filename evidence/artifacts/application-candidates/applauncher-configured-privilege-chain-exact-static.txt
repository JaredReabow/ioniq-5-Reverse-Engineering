[bounded security conclusion]
The recovered configuration and exact kernel semantics close the previously
unknown *configured* label prediction:
  stock init/systemd floor -> AppLauncher floor -> direct-route QProcess child
  retains floor when the caller-controlled executable has no SMACK64EXEC.
The configured uid prediction is root throughout because neither service nor
AppLauncher drops uid/gid.

This is a predicted same-uid App::* -> floor SMACK-domain transition, not a
runtime-demonstrated unrestricted-root transition. It does not prove Request
registration/delivery, a writable object at exec time, QProcess acceptance,
successful exec, actual credentials/capabilities, or owner-unit labels. Floor is
not Privileged under onlycap and does not automatically access Data::*, System::*
or every other label. It has same-label floor access and explicit access to the
enumerated application labels.

A compromised stock app is already configured uid 0 and has an explicit
App::* -> floor rwx rule. The AppLauncher route's defensible incremental effect
is therefore a task-label transition and access to other enumerated application
domains, not a newly established uid-0 transition. Capability retention,
read-only-root remount behavior, update-anchor modification, update acceptance,
partition writing, boot acceptance, rollback, and persistence remain separate.
