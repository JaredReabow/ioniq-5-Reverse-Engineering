## Signature verification of unmodified extractions
unzip extraction : codesign --verify --deep --strict -> exit 1
                   "invalid signature (code or signature have been modified)"
ditto extraction : codesign --verify --deep --strict -> exit 1, same message
binary alone     : codesign --verify --strict -> exit 1, same message
xattr            : extracted copy carries com.apple.quarantine
Frameworks dir   : present but empty; no symlinks anywhere in the bundle

Conclusion: the vendor signature fails on the archive as published. This is not
an extraction artefact: two independent downloads are identical, directory copy
and zip extraction both fail, and the Mach-O's own embedded signature is invalid.

## Authorised local repair (scratch analysis copy only)
The untouched original was preserved. A separate working copy under /private/tmp
was ad-hoc re-signed and its quarantine attribute removed; only that copy changed.
working binary   : 67749136 bytes sha256 216d392bcc573437...
codesign -dv     : CodeDirectory flags=0x2(adhoc), Signature=adhoc, TeamIdentifier=not set
codesign verify  : exit 0, "valid on disk / satisfies its Designated Requirement"
xattr            : no com.apple.quarantine on the working copy
observed result  : the repaired copy opened to the AU region selector

This is a local workaround, not evidence that the vendor artifact is intact. An
ad-hoc signature proves only that the on-disk bytes match what was re-signed; it
discards vendor identity and must never be treated as a trusted vendor binary.
